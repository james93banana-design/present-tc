# present-tc asset

本包对应用户的《present-tc asset.pptx》，共 **213 页**。包含 202 页内容模板和 11 页插画/地图素材。原版第 1–25 页、228–300 页已从候选索引中剔除，保留页顺序未变。

## 文件

- `typography-spec.md`、`typography-tokens.json`：HTML与PPT各自的字体字号配置。
- `pptx-style-reference.md`：PUBGM字体、层级和排版参考。
- `assets/fonts/`、`assets/typography.css`：参考稿内嵌腾讯体W3/W7和角色样式。
- `layout-hierarchy-spec.md`：内容区展开、外围边距、三层标题与正文对比、模块间距。
- `fixed-canvas-spec.md`：HTML / PPT 固定画布、投屏缩放、转换和验收规则。
- `templates.json`：213 个逐页条目、148 个细分布局族、21 类共享规则。
- `assets/present-tc asset.pptx`：原生模板，共213页；已移除指定品牌文字及标志组合。
- `thumbs/`：对应当前页码的预览图，继承自此前检查过的原页。
- `observations.tsv`：逐页结构与适用场景，含新旧页码。
- `page-mapping.csv`：原 311 页的完整保留/删除与页码映射。

`source_slide` 表示删减版当前页码。`original_slide` 表示原 311 页模板中的页码。稳定 ID 保留原页身份，例如 **tc-027 = 原第 27 页 = 当前第 2 页**。不要把稳定 ID 的数字直接当当前页码。

## 应如何放入 Skill

使用“短指令 + 外部参考 + 原生模板”的组织方式，而不是把所有页面描述嵌入一篇很长的提示词。

建议的目录结构：

```text
SKILL.md                         # 简短的工作流程、检索入口及质量要求
references/present-tc/templates.json    # 本包逐页选型索引
references/present-tc/selection-guide.md
references/present-tc/fixed-canvas-spec.md
references/present-tc/layout-hierarchy-spec.md
references/present-tc/pptx-style-reference.md
references/present-tc/typography-spec.md
references/present-tc/typography-tokens.json
references/present-tc/page-mapping.csv
references/present-tc/thumbs/           # 预览图
assets/present-tc asset.pptx         # 原生模板
assets/fonts/                      # 内嵌腾讯体源文件
assets/typography.css              # 角色字体样式
scripts/                        # 日后实现并验证的复制/填充/导出程序
```

上面只是集成结构建议。本包未创建、安装或修改现有 Skill，也未实现自动填充组件。集成时需要按实际放置位置调整相对路径；本包 JSON 中的路径以包根目录为基准。

### 共用索引，按输出格式分流

可直接放入 Skill 的简短规则：

> 先按内容关系与信息容量检索 `present-tc asset`，查看 1–3 个候选的索引和预览图，确认适配后再制作。PPT 输出复制原生模板页并修改；HTML 输出参考同页的视觉结构，在固定16:9画布上重建并逐页播放。两种输出共用画布比例、布局数据和内容字段；投屏只做整页等比缩放。具体遵循 `fixed-canvas-spec.md`、`layout-hierarchy-spec.md` 和 `typography-spec.md`：HTML加强字号与内容区宽度（中文腾讯体、英文Arial）；PPT字体与排版主要参考PUBGM（`pptx-style-reference.md`）。两种输出分别渲染验收，不硬套相同字号。

- 先确定目标格式，再选模板；不能因为参考源是 PPTX 就默认输出 PPT。
- 索引用于判断结构与场景，预览图用于确认配色、比例和层级，PPTX 用于读取原生对象及精确布局。
- 两种输出均保留统一画布比例、信息关系、主次层级和关键视觉特征；所有示例数据和文案必须替换。数量图形必须随新数据重算。
- 同一内容同时输出 PPT 和 HTML 时，共用数据、语义字段和画布坐标，保持页序与主要模块位置一致。

### PPT 输出优先保留原生结构

要接近原模板，优先从 `assets/present-tc asset.pptx` 复制所选页面，在原有对象中替换内容。保留页面尺寸、母版、主题、颜色、坐标、组合关系、图片裁切和关联资源；字体与字号默认按 `typography-spec.md` 的PPT配置及PUBGM风格设置，只有用户明确要求原样复刻字体时才沿用模板字体。不要只读文字描述后凭印象重新画一页。

每种常用版式后续可补充真正的“填充契约”：哪些对象是标题、正文、图片或图表，必填项是什么，数量不符和文字过长时如何处理。对象绑定需要对原页单独检查和测试，本次索引不能替代它。

复制原页也不能保证最终显示完全一致。应检查字体是否可用、内容是否溢出，以及图表和形状是否在编辑/导出中保留；最终渲染并与源页对照。图表的原生可编辑性需逐页验证，不能因扩展名为 PPTX 就认定所有图都可直接改数。

### HTML 输出需要独立实现

PPTX 可作为视觉和结构依据，但不是 HTML 组件。HTML 用 HTML/CSS 实现布局，按需要使用 SVG 或图表组件；文字、模块、表格和图表应保持独立结构，不能把整页截图当作完成的 HTML。

HTML 汇报默认采用固定画布的逐页演示，遵循 `fixed-canvas-spec.md`。本资产使用1280×720逻辑画布（16:9）；所有页面尺寸固定，屏幕变化只触发整页等比缩放并双向居中，页面内的模块和文字不响应浏览器宽度而重排。内容过多时调整文案、模块或拆页，不按内容高度缩小整页。

只有用户明确要求时才另行制作可重排的阅读版；阅读版不得成为投屏或PPT导出的排版依据。全屏工具栏悬浮，不占底部高度。同屏比例时铺满可用窗口，异屏比例时只保留必要的对称边带，不拉伸、不裁切。

筛选、悬停详情、点击展开，以及拖动、缩放和表格编辑，均为按需求另行实现的功能；不会因引用本 asset 自动具备。交互应服务内容，不为装饰而添加。

完成后与源页预览对照检查布局、文字溢出、比例和图表数值，并按固定画布契约检查不同窗口和全屏状态的缩放与居中；实现了交互的，还需检查实际行为。只有经过实现和验证的 HTML 组件才可标注为可直接调用。本包当前提供参考资产与选型规则，尚未提供 HTML 组件库。

## Skill 的判断顺序

1. 用一句话确定本页表达目的，再识别信息关系，如对比、趋势、构成、拆解、流程、层级。
2. 区分 `content_template` 和 `asset_sheet`，只有需要插画或地图素材时才召回素材页。
3. 以每页 `rule_ids` 为准，读取对应的 `selection_rules`。**单页规则优先于布局族默认值**，混合页面按实际面板判断所需输入。
4. 检查数据和语义前提。风险矩阵需要已确认的概率/影响分级，瀑布需要可对账的增减值，组织关系不能由排版推断。
5. 按槽位和结构筛选，分别匹配对象数、指标数、时间点和阶段数。“4 方案 × 5 维度”不能当作任意 20 个要点。
6. 按文字容量、投屏或阅读场景、重点位置排序；颜色只是后续选择。相似变体不要占满候选结果。
7. 加载 1–3 个候选的详情和缩略图，返回当前页码、稳定 ID、适配理由、缺失输入及调整要求。
8. 按目标格式制作：PPT 复制原生页并替换；HTML 按同页视觉结构重建，或调用已验证的 HTML 组件。分别渲染、核对内容与数据，并检查实际使用场景。

**不要每次把全量 JSON 放入提示词。** 先读简短规则，再通过程序按角色、关系、数据条件和槽位筛选，仅读取少量候选页。

## 数量和数据的边界

- `observed.slots` 是实际观察的主要槽位，不是文本框和图形数量的完整清单。
- `slot_counts` 会区分多个交叉维度。无法可靠结构化的描述保留 `raw` 并标记为未解析，不应当作硬筛数字。
- `recommended_capacity` 是基于实际槽位的适配建议，不是经过所有长度文案测试的字数上限。混合页需要逐面板检查。
- 模板里的数字、日期、人名、机构名和结论均为示例，不可带入用户的实际汇报。
- 柱高、气泡面积、环图角度、点阵数量、色阶和瀑布基数应随真实数据重新计算。只改标签不改几何会误导。
- 圆环、箭头、拼图等示意形状不自动表达数量、比例或因果。
