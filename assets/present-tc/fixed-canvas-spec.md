# HTML / PPT 固定画布契约

## 默认模式

汇报材料默认采用固定画布、逐页切换、整页等比缩放。HTML 和 PPT 使用同一页序、画布比例、模块边界与信息层级。只有用户明确要求网页阅读版时，才另建可重排的阅读视图；不得让阅读版样式影响演示与导出。

本资产的 PPT 页面尺寸是 12192000 × 6858000 EMU，对应 1280 × 720 CSS px（16:9）。以此作为默认逻辑画布；如用户提供其他比例，读取源尺寸并统一修改全稿。1920 × 1080 屏幕只是显示尺寸，不是另一套排版。

## 三层结构

1. **播放窗口 viewport**：使用实际可用容器的宽高。全屏时铺满当前屏幕，清除网页外层的 margin、padding、max-width、侧栏占位及底部工具栏占位。
2. **缩放框 frame**：只负责整页缩放和水平、垂直居中；它的显示尺寸为 `W × s`、`H × s`。
3. **逻辑画布 canvas**：固定 `W=1280`、`H=720`，使用 `box-sizing:border-box`。模块、表格、图表、字体、内边距均按逻辑画布定义。可用固定网格或绝对坐标，不能按浏览器宽度重新排版。

缩放只能在 frame/canvas 交界执行一次。子模块禁止再按屏幕大小整体缩放。固定画布外层可 `overflow:hidden`，但不能用它掩盖内容溢出；交付前必须检查所有内容边界。

## 唯一缩放算法

设可用窗口为 `Vw × Vh`，逻辑画布为 `W × H`：

```js
const scale = Math.min(Vw / W, Vh / H);
const renderedWidth = W * scale;
const renderedHeight = H * scale;
const left = (Vw - renderedWidth) / 2;
const top = (Vh - renderedHeight) / 2;
```

- 允许放大，不得用 `Math.min(1, scale)` 把大屏画面锁在小尺寸。
- 用未变换的 viewport 尺寸计算，不要用已缩放画布的 `getBoundingClientRect()` 再算缩放。
- 不用 `scrollHeight`、`scrollWidth`、正文长度或每页 minimumHeight 计算画布尺寸或缩放。内容溢出是排版问题，不能通过缩小整页来隐藏。
- 不使用 `cover`、非等比拉伸或裁切正文来强行填满不同屏幕。
- 监听容器尺寸变化、窗口 resize、fullscreenchange；在事件后的动画帧中重算。字体与图片加载后检查内容溢出，不改变逻辑画布。
- 全屏以当前播放窗口为准，支持退出全屏后恢复；若全屏请求失败，窗口内仍按相同算法播放。
- 页码和上一页/下一页采用不占布局空间的悬浮控制。默认淡出，键盘焦点进入时恢复；不遮挡必读内容，不永久扣除底部高度。

## 留白的判断

区分模板内部的设计留白与屏幕比例不同产生的画布外边带。前者按所选模板保留，后者只允许由上述公式产生，并且对称居中。

| 可用窗口 | 1280 × 720 画布显示结果 | 允许的外边带 |
|---|---|---|
| 1920 × 1080 | 1920 × 1080，s=1.5 | 无 |
| 1280 × 720 | 1280 × 720，s=1 | 无 |
| 1920 × 1200 | 1920 × 1080，s=1.5 | 上下各60px |
| 1024 × 768 | 1024 × 576，s=0.8 | 上下各96px |
| 2560 × 1080 | 1920 × 1080，s=1.5 | 左右各320px |

等比、完整显示和任意屏幕零边带不能同时满足。默认保证比例与完整内容；如需另一比例的版本，重新排版生成，不在投屏时临时拉伸。

## 内容与模块

画布内部的内容区与层级遵循 `layout-hierarchy-spec.md`，固定比例本身不等于版面已经饱满。

- 每页为一个固定画布，翻页只切换可见页，不改变画布大小。鼠标与键盘均可翻页，不能有演示页内部滚动条。
- 页边距、标题区、正文区和页脚使用统一母版规则；套用参考页时继承该页的模块位置、比例和配色。模块数量可按内容调整，但需在同一画布内重新检查布局。
- 内容超量时依次精简文案、调整模块、拆页或移入备注/附录。禁止自动降低全页缩放、无限增高页面或把正文字号缩到不可读。
- 动态展开不把其他模块向下推；采用预留区域、固定尺寸浮层或新增页面。图表尺寸固定，数值更新只改变数据对应的几何。
- 字体与字号按 `typography-spec.md`、`typography-tokens.json` 执行。字体必须可用，图表与图像必须加载完成；字体替换和语言变化都要重新检查换行。浏览器窗口改变时，固定画布内的换行与模块位置应保持不变。

## PPT / HTML 共同布局数据

逐页记录 `id`、`canvas.width`、`canvas.height`、模块 `x/y/width/height`、字体、字号、行距、对齐、颜色、图像裁切、图表数据及备注。字体字号另按输出格式记录；尽可能让两种输出消费同一份内容与相对布局数据，而不是先做任意网页再猜测 PPT 坐标。

坐标映射：`pptX = x / canvasWidth × pptSlideWidth`，其余坐标和尺寸同理。本模板在96dpi逻辑画布下，1px对应9525 EMU，几何等比转换时字号1px对应0.75pt（不是新稿PPT默认字号，默认按格式分别选用typography-spec.md配置）；若另设 PPT 物理尺寸，使用比例映射，不能硬套常数。

正文使用原生 PPT 文本框，表格和图表尽量转换为原生对象；矢量插图按兼容性使用 SVG 或图片。复杂 CSS、动画、筛选、悬停与编辑器不能承诺无损转换：指定静态导出状态，把必要详情放在页面或备注中。保留视觉效果的截图导出必须明确标注为不可逐对象编辑，不能冒充原生可编辑转换。

导出必须读取完整、未缩放的逻辑画布，不截取浏览器视口，也不包含播放器边带、控制栏或阅读版滚动布局。PDF 一页对应一张画布，PPT 一页对应一张幻灯片，页序一致。

## 验收门槛

1. 在表中的五种窗口尺寸验证 scale、显示宽高和居中偏移；误差仅允许像素取整（1px以内）。同一窗口下所有页面的外框尺寸一致。
2. 检查普通窗口、进入/退出全屏、窗口调整及上一页/下一页；无侧栏残留、工具栏占位、重复缩放、裁切或意外滚动。
3. 每页检查文字和模块边界，尤其是最密集表格、最长标题、图表图例、语言切换与展开后的状态。不能只检查封面。
4. 对齐逻辑画布后，比较 HTML 与 PPT 的主要边界、字体换行、数据和图像裁切。允许渲染器的细微字形差异，但不接受模块错位或内容丢失。
5. 区分“规则已定义”“播放器已实现”“全稿已验证”。本契约本身不表示旧 HTML 已修复或转换器已实现。
