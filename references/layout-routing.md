# 版式选型

先用一句话说明本页关系，再选择一个主要表达。普通文字修改跳过此步骤。以下为通用信息结构，不是第三方模板的页面目录。

| 信息关系 | 推荐表达 | 必须具备的内容 | 注意事项 |
|---|---|---|---|
| 简短说明 | 正文或短列表 | 要说明的事实或判断 | 不强行三卡片 |
| 两方差异 | 双列对照或对比表 | 两个对象、相同维度、差异 | 不编造对照方 |
| 阶段递进 | 步骤链或阶段表 | 实际步骤、方向、阶段输出 | 不把并列关系画成因果 |
| 时间演进 | 时间轴或路线图 | 已知时间、事件、状态 | 预测与承诺分开 |
| 问题与方案 | 问题/证据/措施映射表 | 已知问题、依据、建议 | 建议不冒充已确认行动 |
| 二维定位 | 矩阵或热力表 | 两个有定义的维度、位置依据 | 无评分依据时不用精确落点 |
| 核心数字 | 关键数字加上下文 | 数值、单位、期间、分母或比较基准 | 不孤立放大数字 |
| 趋势比较 | 折线或柱状图 | 同口径可比较数据 | 标注期间、单位及缺失值 |
| 构成占比 | 堆叠条或构成表 | 分类口径、总量、份额 | 检查总和；不强制饼图 |
| 层级与接口 | 树、泳道或关系图 | 节点及已知关系 | 箭头含义明确，复杂图配文字解释 |
| 多对象多维核对 | 表格或清单 | 行列含义与核对依据 | 精确值优先表格 |
| 封面与结语 | 主标题、目的或有据结论 | 主题、必要上下文 | 不放虚构口号或承诺 |

## 选择与复用

1. 优先保留源材料中已经清楚的表达；用户允许且图示能提升理解时再新增。
2. 使用随附present-tc asset，先读取每页摘要索引筛选1–3页，再看预览与原生对象确认。索引和预览随本技能打包，主入口只保留短引导。索引不是可直接填充的组件；对象槽位、容量、数据绑定需另行检验。
3. 按真实内容调整槽位数量；可以合并、删减，不为凑满模板制造事实。
4. HTML参考同一模板的视觉结构，在固定16:9画布重建；PPT复制原生模板再修改。两者共用内容、页序和模块相对位置，应用各自字体配置。网页流式阅读仅在用户明确需要时作为独立视图。
5. 连续三页相同框架时重新检查内容关系，必要时以表格、对比、流程或正文替换，而非只换卡片颜色。

## 可选能力

复杂关系可调用实际可用的图示能力；准确数字可调用图表能力；原创插画仅用于需要的主视觉。任何能力都服从当前报告的字体、配色和层级，不各自使用一套主题。能力缺失时使用简单表格或原生图形，不虚构工具和私有依赖。

## 索引资产契约

索引每页保留稳定id、当前页码、原始页码、核心摘要、适用场景、输入需求、容量、布局族、预览路径、原生模板路径及限制。删减后剔除未保留页，不把稳定id后面的数字当当前页码。更新资产后重新核对页码映射，候选总数以实际索引为准。

采用“摘要初选→模板对比→确认适合→模板基础修改”。模板文字、示例数字和图标不当作业务事实。已删除的原模板品牌文字和标志不可重新引入。模板可供HTML视觉参考，原生PPT仍是对象坐标及可编辑性验证来源。

素材随完整仓库放在assets/present-tc，保留包内templates.json、page-mapping.csv、thumbs、原生pptx和字体的相对关系。

## 随附完整素材包

从技能根目录读取 `assets/present-tc/selection-guide.md` 与 `assets/present-tc/templates.json`；缺失时先指出下载或安装不完整，再按实际任务使用通用版式继续。逐页 `thumbnail` 与 `source_asset` 路径均以这个素材包根目录解析；原生PPT和字体位置以实际索引与选型说明为准。字体别名按HTML实现统一映射，WOFF2用于HTML内嵌，不能直接冒充可安装或可嵌入PPT的TTF/OTF；PPT端检查字体可用性。先选1–3页再读取对应预览和原生对象，不逐页全量加载。
